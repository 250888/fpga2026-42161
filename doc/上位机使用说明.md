# 瞬迹 上位机使用说明

面向队友：拿到 `上位机.html` 之后怎么在电脑上跑起来、界面每一块什么意思、出问题怎么查。

上位机是单文件 HTML，通过浏览器 Web Serial API 直连 FPGA 串口，**零安装**，可从 U 盘运行。串口参数固定 **115200 8N1**，页面打开端口时自动使用，无需手动设置。

---

## 1. 环境要求

| 项 | 要求 |
|---|---|
| 浏览器 | Chrome 或 Edge（Chromium 内核）。Web Serial API 需要较新版本，建议直接用最新版；最低可用版本以实测为准（参考下限约 Chrome/Edge 89）。Firefox、Safari 不支持，页面会弹「当前浏览器不支持 Web Serial」 |
| 操作系统 | Windows（串口枚举）。浏览器能枚举到 COM 口即可 |
| 串口驱动 | 板子经 USB 转串口连电脑。若设备管理器里看不到 COM 口，装对应转接芯片的驱动（CH340 / CP2102 等，以实际使用的模块为准） |
| 其它软件 | 不需要。Python、Node、串口助手一概不用（本地服务兜底方式除外，见 3.2） |

---

## 2. 三种打开方式

### 2.1 直接双击文件（默认方式）

双击 `上位机.html`，默认浏览器打开即可。若默认程序不是 Chrome/Edge：右键 → 打开方式 → 选择 Chrome/Edge。

### 2.2 本地服务（浏览器拦截串口时的兜底）

页面自带说明给出的方案，命令可直接复制（cmd）：

```bat
cd /d "E:\d\UserFolders\Desktop\嵌赛FPGA\瞬迹\doc"
python -m http.server 8080
```

然后浏览器访问：

```
http://localhost:8080/上位机.html
```

需要本机装有 Python。仅在双击打开时串口被浏览器拦截才需要走这条路。

### 2.3 从 U 盘运行

把 `上位机.html` 拷到 U 盘，目标电脑上用 Chrome/Edge 打开。同样零安装，适合现场演示、给评委拷贝。

## 3. 首次连接串口

前提：硬件链路就绪——**EGO1 已烧录**（见第 6 节红线）、J5 排线接牢、JA/JB 公头线束接好、**SW0 拨到 ON**。

1. 点右上角「**连接串口**」按钮。
2. 浏览器弹出端口选择框，列出系统里的串口（如 COM4）。**若列表为空**，说明驱动/接线问题，见第 7 节排查表。
3. 选中端口 → 确认。Chrome 首次会询问「网站想要连接到串口设备」，勾选「记住我的选择」，以后不再弹。
4. **成功标志**：右上角圆点变绿，状态文字从「未连接」变为「COM · 115200 8N1」，按钮变为「断开」，读数带开始刷新。
5. 用完再点一次「断开」释放串口。点下后按钮短暂显示「断开中…」并禁用，**浏览器真正释放端口后**才恢复为「连接串口」——若串口没真正释放，下次点「连接串口」会报"串口被占用"。断开在**收到数据和没收到数据（SW0 未开）两种状态下都可靠**；若长期卡在「断开中…」，刷新页面即可强制释放。

## 4. 界面区块说明

页面从上到下共六块：

| 区块 | 内容 | 怎么读 |
|---|---|---|
| 顶部状态行 | 圆点 + 状态文字；四个按钮：连接串口 / 演示 / 全屏 / 导出证据 | 状态文字：「未连接」→「COM · 115200 8N1」（已连真机）；「演示数据 · 模拟」（演示模式）；「数据已停止」（1.5 秒收不到字节，看门狗触发，灰字）；「已断开」 |
| 状态读数带 | 左侧大字状态 + 右侧 4 个指标 | 见下方两表 |
| **实时连接数历史条** | 一条满幅条带，每格 = 一帧（约 40 fps 采样，共 180 格 ≈ 8 秒），右侧最新 | 条带高度 = 当前连接数占 16 的比例。**琥珀 = 16 路全通，橙 = 缺路，红 = 全断**。断线的那一帧会在条带上留下缺口，恢复后缺口仍然保留 —— 这是"瞬态捕获"最直观的证据，讲解时可以指着缺口说"这一帧掉过" |
| 拓扑矩阵 · 行 A × 列 B | 16×16 格子 | 行 A_a × 列 B_b 亮 = A_a 与 B_b 导通。**对角线 = 琥珀实块 = 1:1 直通**；非对角红块 = 错接；整行暗红 = 该 A 通道 stuck（空闲态被拉低）；整行更暗 = 该 A 通道当前无任何连接 |
| 线束连接图（SVG） | 左 A 端、右 B 端，16+16 个圆点 | 水平琥珀实线 = 1:1 直通；红色曲线 = 错接（会交叉，一眼看出接错了哪两根）；暗灰虚线 = 期望位（对角）但当前断开；圆点变红 = 该通道 stuck |
| 通道健康 | Open 条带 + Stuck 条带，各 16 格（编号 0–15） | Open 格点亮 = 已连接，灰 = 未连接/开路（鼠标悬停有文字）；Stuck 格变红 = 空闲态被拉低，判故障 |
| 事件记录 · 捕获时刻 | 毫秒级时间线 | 四类行：连接建立（A_i → B_j）/ 连接丢失 / 状态跳变（cls 变化）/ 系统消息（用户断开、读取中断、串口被拔出）。时间戳为本机接收时刻 `HH:MM:SS.mmm` |

### 4.1 读数带的 4 个指标

| 指标 | 含义 | 正常值 |
|---|---|---|
| 连接数 | 当前有导通的 A 端通道数 | 接满 1:1 线束时 16/16 |
| 帧 / 秒 | 解析速率 | 约 240（48 字节 @ 115200 的满速） |
| 序号 | 帧序号（协议 Seq 字段） | 连续递增；不动 = 没收到帧 |
| CRC 校验 | 通过帧占比 | 100%；下降说明链路有坏帧 |
| 其它帧 | 非矩阵帧计数（未知 type / 未知长度，已正确校验 CRC） | 0；>0 时读数带角落出现琥珀小字「其它帧 N」。正常运行时恒为 0，未来扩展帧类型才会涨 |

### 4.2 状态大字（cls 状态码，由 FPGA 判定后随帧上报）

| cls | 显示 | 含义 |
|---|---|---|
| 0 | PASS（绿） | 全部通道按基准拓扑导通 |
| 1 | OPEN（琥珀） | 存在开路（线断 / 未接） |
| 2 | MISWIRE（红） | 存在错接——A 端接到了错误的 B 端 |
| 3 | BRIDGE（红） | 存在短接——多路并联 |
| 4 | ANOMALY（棕） | 瞬态异常 |
| 5 | NO_REF（黑） | 未学习基准拓扑——按 EGO1 的 **BTN1** 学习 |

**上电后第一件事**：矩阵显示的是实际测到的导通关系，与 cls 无关；接好线束后按 BTN1 学习基准，cls 从 5 变 0，此后才开始与基准比对报故障。

## 5. 演示模式与证据导出

| 按钮 | 作用 |
|---|---|
| 演示 | 无硬件时用模拟数据排练界面与流程。50 ms 一帧，脚本依次：先是 8 通道 1:1（cls 5）→ 出现错接 A3→B11（cls 2）→ ch5 开路（cls 1）→ ch9 stuck（cls 1）。连接真实串口会自动停止演示。**演示数据不是硬件数据**，正式证据必须用真机采集 |
| 全屏 | 切换答辩全屏版式。隐藏报头副标题与底部说明，放大状态词（62px）、连接数（52px）、矩阵格（25px），连接图撑满面板。**版式按 1920×1080 精确排布，全屏时整页高度正好 1080px、不出现滚动条**——录演示视频就用这个模式。投影时同样用它，不要用浏览器 F11（F11 只去掉浏览器边框，页面本身不会放大） |
| 导出证据 | 下载 `xunji_证据_<时间戳>.txt`，内容 = 导出时间 + 当前 cls + 连接数 + 其它帧/CRC 失败计数 + 事件时间线（界面最多显示最近 300 条，导出最多 3000 条）。导出的是**事件记录，不是原始帧**。注意：文件名时间戳为 UTC，文件头「导出时间」为本机时间 |

### 5.1 快捷键

| 键 | 作用 |
|---|---|
| `F` | 全屏 / 退出全屏（Esc 也可退出） |
| `D` | 切换演示模式 |
| `E` | 导出证据 |
| `C` | 连接串口 |

按住 Ctrl / Meta / Alt 的组合键、以及输入框获得焦点时不会误触发。全屏版式用 Fullscreen API 进入，若浏览器拒绝授权则只切换版式、不进真全屏，功能不受影响。

### 5.2 断线提示

串口读取中断、串口流结束、设备被拔出，或**连续 1.5 秒收不到任何字节**时：状态点转灰、状态词变灰显示「数据已停止」，事件记录里写明原因。数据恢复后状态点自动变回绿色并在事件记录里记一条恢复消息，无需手动操作。

## 6. 特别强调（硬件红线，踩过的坑）

1. **JTAG 配置是易失的**：EGO1 每次断电 / 重插 USB 后都要用 Vivado 重新烧录，否则 FPGA 未配置。未烧录时 IO 全是高阻——上位机没数据，万用表读数也无意义。
2. **JA / JB 是 2×10 IDC 母座（孔）**：对接必须用 **2×10 公头**（双排针或 IDC 公头排线）。杜邦线直接捅母座接触极差，会造成通道随机失效——这是实际踩过的坑。
3. **针脚约定**：JA 1–16 针 = A0–A15，JB 1–16 针 = B0–B15；**17–20 针是 NC，不要接线**；红线对齐 pin1。
4. **万用表量电压的两个前提**：量 IO 前必须先烧录过（否则高阻，读数无意义）；量 FE 板供电轨对地之前**必须先拔 J5 排线**，否则量到的是 EGO1 板 3.3V 轨阻抗。

## 7. 常见问题排查

| # | 现象 | 原因 | 处理 |
|---|---|---|---|
| 1 | 点「连接串口」弹「当前浏览器不支持 Web Serial」 | 浏览器不是 Chromium 内核，或版本太旧 | 换最新版 Chrome / Edge；仍不行走 2.2 本地服务 |
| 2 | 端口选择框里没有 COM4，或列表为空 | USB 转串口驱动没装 / USB 线只接了供电 / COM 号变了 | 设备管理器确认实际 COM 号；装驱动；重新插拔 USB |
| 3 | 弹「串口打开失败：……可能被其它程序占用」 | 串口被串口助手、`xunji read` 或另一个浏览器标签占用 | 关掉占用程序后重连；不行就拔插一次 USB |
| 4 | 连上了但页面没数据：帧/秒 = 0，序号不动 | SW0 没拨 ON / FPGA 没烧录（断过电）/ J5 排线没接好 | 拨 SW0；用 Vivado 重烧；检查 J5。**断电重插后必须重烧** |
| 5 | 序号不连续，或 CRC 校验 < 100% | USB 线/转接板接触差、干扰 | 换短一点的 USB 线、确认 115200、避开干扰源。CRC 长期偏低说明链路不可靠，此时的证据不可用 |
| 6 | 连接数不够 16，Open 条带有灰格 | 杜邦线捅母座接触不良 / 排线没压好 / NC 针误接 | 换公头对接；红线对齐 pin1；17–20 NC 不接；压紧排线。缺失通道若等间隔出现（如第 3、6、9 路），直接查排线与连接器；故障通道随插拔移动 = 接触问题，固定不动 = 查焊点/器件 |
| 7 | cls 一直是 5 NO_REF | 没按 BTN1 学习基准 | 接好基准线束后按 BTN1，学习后应变 0 |
| 8 | cls = OPEN 但看着线都接着 | 某通道空闲态被拉低或断路 | 看 Stuck 条带和矩阵整行，定位通道号后查该路硬件 |
| 9 | 页面打开是空白或样式错乱 | 被 IE / 其它默认程序打开 | 右键 → 打开方式 → Chrome / Edge |
| 10 | 点「连接串口」没反应或报安全错误 | 当前环境限制 file:// 下的串口访问 | 走 2.2 本地服务方式 |
| 11 | 连着连着状态词变灰「数据已停止」 | 连续 1.5 秒没收到任何字节：SW0 被拨回 OFF / FPGA 断电未重烧 / USB 线松动或被拔 | 拨回 SW0；用 Vivado 重烧；插紧 USB。数据恢复后状态点自动变绿，无需重连 |
| 12 | 读数带角落出现「其它帧 N」 | 收到了 CRC 正确但 type 或长度不是矩阵帧的数据 | 正常运行时恒为 0。若持续增长说明链路里混入了别的设备的数据，检查串口选的是不是 COM4 |

## 8. 协议速记（排查/二次开发用）

```
55 AA | Ver(1) | Type(1) | Len(2, LE) | Seq(2, LE) | Payload | CRC-16(2, LE)
```

- 矩阵帧：Type=1，Len=38。Payload 前 32 字节 = 16×16 矩阵，**小端位打包，bit index = a×16 + b**（a = A 端 0–15，b = B 端 0–15，置 1 = 导通）；随后 open_flags 2B、stuck_low_mask 2B、cls 1B、ts0 1B。
- CRC-16/CCITT-FALSE：多项式 0x1021，初值 0xFFFF，不反转，无终值异或，覆盖 Ver 到 Payload。
- 帧率约 240 fps（48 字节 @ 115200）。
