# 瞬迹 XUNJI · 线束动态诊断工作台

这是针对现有 EGO1 / FE-16 项目重做的上位机。单文件 HTML 内置所有样式、脚本与图形，无 CDN，不上传串口数据，不需要安装前端依赖。

## 立即打开

**查看界面或排练**：用 Chrome / Edge 打开同目录的「瞬迹诊断工作台.html」，点击右上角「模拟演示」。顶栏始终标注「模拟数据 · 非实测」。左侧「演示」页提供 42 秒自动流程，诊断页支持手动注入单种故障。

**连接真实 FPGA**：解压完整压缩包，双击「打开瞬迹工作台.bat」。启动器需要 Python 3.8+，仅在 127.0.0.1 的自动空闲端口启动本地服务，并打开浏览器。如果默认浏览器不是 Chrome / Edge，请复制启动窗口中的地址到 Chrome / Edge。

启动窗口需要保持开启。使用结束后在窗口按回车，服务随即停止；HTML 文件仍可离线查看。直接打开 HTML 时若浏览器限制串口权限，请使用本地启动器。

## 真机操作顺序

1. EGO1 烧录完成，FE-16 排线接牢，SW0 开启扫描。断电后的重新烧录要求沿用原项目说明。
2. 点击「连接串口」，选择设备对应端口。串口固定 115200、8 数据位、无校验、1 停止位、无流控。
3. 接好正常线束，**在 EGO1 按 BTN1** 学习硬件基准。网页不发送未定义的学习命令。
4. FPGA 输出 PASS 后，主机从该正常帧留存拓扑；允许正常接法本来就是交叉连接，不默认把所有非对角格判错。后续出现不同的 PASS 拓扑时，主机同步留存该正常拓扑，并保留旧帧各自的基准。
5. 依次制造开路、错接、短接，每次先复原至 PASS 再进行下一种。FPGA 状态码保留原含义：0 PASS、1 OPEN、2 MISWIRE、3 BRIDGE、4 ANOMALY、5 NO_REF。
6. 在「取证」页选择故障事件，核验帧序号、主机接收时间、矩阵和 Open / Stuck 标志，再导出会话。

软件会在 **1.5 秒未收到有效矩阵帧** 时标注中断，即使串口仍持续收到噪声字节。随后收到有效帧会自动恢复。连接与模拟各自创建新会话；切换前请导出需要保留的记录。停止模拟或断开设备保留当前记录及原数据来源标签。

## 界面与快捷键

| 位置 / 操作 | 作用 |
|---|---|
| 诊断 | 实时矩阵、端到端拓扑、故障建议、最近 12 秒变化、最新事件 |
| 取证 | 筛选事件、选择故障快照、拖动保留帧、按原接收节奏回放、导入 JSON |
| 链路 | 硬件采集链路、协议字段、传输时间计算和应用场景说明 |
| 演示 | 六个分镜与 42 秒自动模拟流程 |
| 点击矩阵或 A 端标签 | 聚焦该 A 通道，再次点击取消 |
| 点击事件 | 查看事件当时的矩阵；采集继续，不会因画面暂停漏记已收到的帧 |
| Space | 冻结 / 返回最新画面 |
| C / D / F / E | 串口 / 模拟 / 录屏全屏 / 导出 |
| Esc | 退出全屏；关闭弹窗由浏览器原生对话框处理 |

导通点和导通 A 通道不是同一个指标。例如 B02 与 B03 短接的模拟场景中，A 通道仍为 16，但导通点增加至 18。错接场景的导通 A 通道仍为 16，正常拓扑差异为 4 bit。

建议 1920×1080、浏览器缩放 100%，按 F 进入录屏版式。需要说明硬件实测时，保持右上角真机来源标签可见。

| 时间 | 镜头与操作 | 建议讲解 |
|---|---|---|
| 0:00–0:15 | 硬件近景接电脑画面；展示正常 16 路矩阵 | “系统重建完整连接关系，检测不只看总导通数。” |
| 0:15–0:35 | 拔开 A05↔B05，停留后复原 | “开路精确落到缺失的连接对；复原过程同样留痕。” |

| 0:55–1:15 | 并接 B02 与 B03，展示 FPGA BRIDGE；复原 | “多余导通点与 FPGA 状态共同区分短接和开路。” |

## 时间与证据口径

- **FPGA 扫描时间**、**串行传输时间**和**整机故障响应时间**是不同指标。
- 48 字节 × 10 bit / 115200 = **约 4.17 ms**，仅为 8N1 下的理论串行传输时间，理论满载约 240 帧/秒。真实接收率在页面单独统计；模拟模式目标约 50 帧/秒，会受系统调度影响。
- 事件的 `t` 为 **PC 系统时钟接收时刻**。同一串口数据块内的多个帧可能具有相同时间戳，无法据此推导硬件精确故障时刻。`elapsed` 为独立的单调接收偏移，用于回放和时间轴；即使系统时钟回调，也不打乱接收顺序。
- 当前协议的 `ts0` 仅有一个字节，原材料未定义计时单位及回绕规则，因此只显示原始值，不推算微秒时间或硬件故障持续时间。
- NO_REF 时，主机不判断与未知正常拓扑的差异。诊断类型来自 FPGA；主机定位信息来自矩阵与留存正常帧的比对。
- 硬件扫描性能、最小可检出脉宽和从故障发生到告警的时延，需要配合信号源 / 示波器 / 逻辑分析仪及重复测量另行验证。本次不修改 FPGA 固件，也不新增硬件测量能力。

## 导出和回放

| 格式 | 内容和用途 |
|---|---|
| JSON | 正常基准检查点、保留的有效矩阵帧、主机时间 / 接收偏移、事件、来源与链路统计；可重新导入 |
| CSV | 带来源、接收时间、帧序号、事件类型及连接对的事件清单 |
| TXT | 当前结论、记录范围、CRC / 序号统计和事件时间线，便于提交报告附件 |

**记录范围有上限**：最近 60,000 个有效矩阵帧、6,000 条事件，满后覆盖最早记录。按理论 240 帧/秒计算，60,000 帧约为 250 秒；长流程请分段导出。它不是无限录制器。CRC 错帧不会作为有效矩阵帧留存，只统计失败次数；JSON 不是原始串口字节转储。

导入文件上限 32 MB、60,000 帧，会校验矩阵长度、数字范围、时间值和单调接收偏移。导入后的事件从保留帧重新计算，因此不保证与原始长期会话中已被帧缓冲覆盖的早期事件相同。旧版 TXT 事件文件不包含矩阵，不能用于完整回放。

真机、模拟、回放会话均有明确标签。导入文件所宣称的真机 / 模拟来源未经独立验证；重复导出回放会保留原始自述来源。文件未提供数字签名或第三方真实性认证。
