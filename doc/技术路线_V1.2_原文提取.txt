[Heading 1] 1. 项目定位与最终目标
──表格开始──
核心定位 本项目不是普通“通断测试仪”。静态阶段重建线束连接关系并发现断路、短路、错接；动态阶段利用 FPGA 的多通道并行硬件和统一时基，捕获弯折、振动、松动过程中难以复现的微秒级间歇开路与接触抖动，并保留故障前后波形与事件时间序列。
──表格结束──
一句话主线：静态重建“线怎么接”，动态捕获“线什么时候断”。
45天内的第一版严格限定为16芯、无源、低压线束。先把多通道并行捕获、确定性时间戳和动态微瞬态做深，再考虑接触电阻、动态短路编码检测等扩展功能。

[Heading 1] 3. 总体系统架构
──表格开始──
┌──────────── FPGA ────────────┐ A端16路 → 激励前端 →  拓扑扫描/驱动控制          │                  │              ↓              │ B端16路 → 整形前端 →  输入同步 → 连接矩阵重建    │                  │              ↓              │                  │       Golden Map 比较        │                  │      OPEN/SHORT/MISWIRE      │                  │                              │                  │   16路并行 Event Detector    │                  │      ↓ 统一 Timestamp        │                  │   Event FIFO / 时序关联      │                  │      ↓                       │                  │   Pre-trigger BRAM Buffer    │                  └──────────┬───────────────────┘                             │ UART/USB                             ↓                     PC 可视化与数据保存
──表格结束──
系统分工原则：PC 只负责显示、保存、报告生成；拓扑重建、故障分类、动态事件检测、时间戳、触发和缓存全部由 FPGA 完成。这样才能保证 FPGA 是系统主体，而不是“采集卡”。
[Heading 1] 4. 已确认主控平台：EGO1 Artix-7 FPGA开发板
主控板已确认就是 EGO1 Artix-7 FPGA开发板，板上搭载 Xilinx Artix-7 XC7A35T-1CSG324C FPGA。这里的“EGO1”是开发板型号，“XC7A35T”是这块开发板上的FPGA器件型号，并不是两块板或两个独立平台。该FPGA属于 AMD/Xilinx 7 Series，符合本赛道器件范围。后续硬件接口、时钟与资源预算均直接以这块 EGO1 开发板为基准。
FPGA资源：XC7A35T 具有 33,280 个逻辑单元、20,800 个6输入LUT、41,600个触发器、90个DSP48E1，以及1,800 Kb片上Block RAM。16路拓扑扫描、并行Event Detector、64位全局时间戳、Event FIFO与Pre-trigger缓存均在资源能力范围内。
系统时钟：EGO1 板载 100 MHz 时钟，SYS_CLK 直接接入 FPGA P17。第一版直接以100 MHz作为统一硬件时基，计数颗粒为10 ns；10 ns仅代表数字时基颗粒，不能等同于整机最终测量精度。
扩展接口：EGO1 的 J5 提供32个双向扩展I/O，每路带板级过流/过压保护。第一版可直接采用“16路A端激励 + 16路B端检测”的32路直连架构，不再需要74HC595扩展。建议先将J5的1～16脚分配给A1～A16，将17～32脚分配给B1～B16，最终在XDC与前端PCB中保持一一对应。
PC通信：EGO1 已板载 USB-UART/JTAG，UART_RX 对应 FPGA T4（FPGA发送端），UART_TX 对应 N5（FPGA接收端），因此不再采购CP2102/CH340。板载2 Mbit异步SRAM可作为后续长窗口波形缓存扩展，第一版优先使用FPGA片上BRAM。
──表格开始──
EGO1固定接口方案 J5共提供32个双向扩展I/O，正好满足第一版16路A端激励 + 16路B端并行检测。建议：J5[1:16] → A1～A16，J5[17:32] → B1～B16。板载USB-UART使用独立FPGA引脚T4/N5，不占用J5资源。因此第一版无需74HC595，也无需外置CP2102/CH340。
──表格结束──

[Heading 1] 7. 实现步骤一：1路线束物理链路验证
不要直接做16路。先搭一条完整物理链，目的是确认电平、边沿、上拉参数与 FPGA 输入方向都正确。
──表格开始──
FPGA OUT → SN74LVC07A → A ===== 待测线 ===== B → SN74LVC14A → FPGA IN                                       │                                      Rp                                       │                                      3.3V
──表格结束──
工作逻辑：LVC07 采用开漏输出。测试时把A端拉低；正常导通时B端被一起拉低；一旦线束开路，B端由 Rp 上拉到3.3 V，经过LVC14整形成清晰数字边沿。LVC14会反相，因此 RTL 中统一对输入做逻辑归一化即可。
原型阶段同时测试 Rp = 1 kΩ、2.2 kΩ、4.7 kΩ、10 kΩ。上拉越小，上升越快，但静态电流越大；最终选择必须基于示波器实测的响应时间、噪声和功耗，而不是凭经验固定。
──表格开始──
第一关验收 示波器同时观察 A、B、LVC14 输出。正常连接、拔线、快速触碰/断开时状态必须与预期一致；FPGA能够稳定读到变化。没有通过这一关，禁止扩16路。
──表格结束──
[Heading 1] 8. 实现步骤二：4路拓扑自动重建
把1路复制成4路，先验证“盲插/认针”核心算法。4根线可以故意交叉，例如 A1→B3、A2→B1、A3→B4、A4→B2。
静态扫描时 FPGA 每次只拉低一个 A 通道，其余 A 通道处于高阻态，然后同时读取所有 B 通道。例如驱动 A1 后只有 B3 响应，则记录 M(1,3)=1。依次扫描所有 A 通道，最终得到连接矩阵 M。
──表格开始──
实际线束： A1 ───── B3 A2 ───── B1 A3 ───── B4 A4 ───── B2  系统输出： A1 → B3 A2 → B1 A3 → B4 A4 → B2
──表格结束──
第一次插入标准线束后按 LEARN，保存参考矩阵 M_ref。之后测试同型号线束得到 M_test，再进行比较。
基本关系可以写成 E = M_test XOR M_ref。具体分类规则：某 A 行没有任何响应 → OPEN；响应位置与参考不同 → MISWIRE；同一激励导致多个本不应连通的 B 响应 → SHORT/BRIDGE。
──表格开始──
第二关验收 4路任意交叉连接能够自动输出正确拓扑；人为制造开路、错接和桥接后，故障分类完全正确。通过后再画16路正式前端。
──表格结束──

[Heading 1] 10. 实现步骤四：动态并行瞬态捕获
静态拓扑测试完成后切换到 DYNAMIC MODE。第一版动态模式专门解决间歇开路和接触抖动，不同时追求所有动态短路类型。
动态模式下，把所有属于正常连接的 A 通道拉低；正常线束使对应 B 端维持低电平。一旦某根线瞬间开路，B端被上拉并产生边沿。FPGA 内部每个通道拥有独立 Event Detector，因此16路不是轮询，而是同时工作。
──表格开始──
正常： CH07 ─────────────────────────────  故障： CH07 ───────────┐     ┌────────────                        └─────┘                          8 μs
──表格结束──
每个事件至少记录 Channel、T_start、T_end、Duration、Count。Duration = T_end - T_start。最低可靠故障脉宽不提前承诺，以后通过可控故障发生器实测确定。

[Heading 1] 12. 统一时间戳与“故障时序关联”
所有通道直接共享 EGO1 的100 MHz系统时钟，因此全局64位Timestamp每10 ns递增一次。故障持续时间通过事件起止时间戳差值计算。需要特别说明：前端LVC07/LVC14传播延迟、线束RC、异步输入采样与同步器都会引入额外误差，因此“10 ns计数颗粒”不能宣传为“10 ns整机测量精度”；最终测量误差必须由示波器标定实验给出。
──表格开始──
事件窗口示例： CH07      0 μs     Intermittent Open CH11     +3.4 μs   Bounce CH12     +9.1 μs   Open
──表格结束──
正式表述使用“故障时序关联”或“事件时间序列”，不要使用“因果分析”。时间先后可以帮助工程师定位故障传播过程，但不能单独证明物理因果。
[Heading 1] 13. Pre-trigger故障黑匣子
Event Detector 负责全速捕获时间；BRAM Buffer 负责可视化回放，两者不必用同样采样率。这样既能保持高时间分辨率，又不会浪费BRAM。
──表格开始──
过去数据                              当前 ██████████████████████████████████████│                                       ↑ Trigger  保存：T_pre（故障前） + T_post（故障后）
──表格结束──
XC7A35T 具有1,800 Kb片上Block RAM。若16路逻辑状态按10 MHz缓存，保存故障前2 ms + 后2 ms共需约640 Kb（约80 KB），第一版可直接放入片上BRAM。Event Detector仍按100 MHz全速运行；若后期需要更长回放窗口，再考虑调用EGO1板载2 Mbit异步SRAM。
[Heading 1] 14. 实现步骤五：独立可编程故障发生器
比赛数据不能靠“手抖一下线束”。必须做一套可重复、可量化的故障源，用另一块MCU控制4066，不让FPGA既制造故障又自己测量。
──表格开始──
A7 ───── SN74HC4066 ───── B7                 ↑           独立MCU定时器
──表格结束──
逐步产生 1 ms、500 μs、100 μs、50 μs、10 μs、5 μs、2 μs、1 μs 等间歇开路。若1 μs依旧稳定，再向500 ns试探；最终论文/报告只写示波器验证后的实际指标。
每种脉宽至少重复500～1000次，示波器同时测量4066控制脉冲和线路实际电平，确认故障持续时间真实存在。

[Heading 1] 16. MCU基线必须公平
MCU使用与FPGA完全相同的模拟前端和故障发生器，采用合理的GPIO中断/定时器捕获或优化扫描，不故意写差。单通道时MCU可能表现很好；项目真正要证明的是随着通道数和事件密度上升，FPGA独立并行检测单元仍能保持确定性，而MCU受中断、调度和串行处理约束。
──表格开始──
答辩中的正确比较 不要说“FPGA主频更高”。要说：FPGA把多个事件检测器映射成真正并行的硬件，各通道共享统一时基；通道数增加时不需要把更多检测任务串行塞进一个CPU执行流。
──表格结束──
[Heading 1] 17. 上位机实现
上位机建议 Python + PySide6/PyQt，仅做显示与数据管理，避免把开发时间浪费在APP和云平台。
拓扑页：显示 A→B 连接图，标出 PASS / OPEN / MISWIRE / BRIDGE。
动态页：显示16路逻辑波形、触发位置、故障脉宽。
事件页：显示时间、通道、类型、持续时间、次数与相关事件。
导出：CSV保存事件，PNG/PDF报告可以后期再加。
通信协议建议采用“固定帧头 + 消息类型 + 长度 + Payload + CRC”的简单二进制协议，避免使用大量ASCII文本拖慢数据传输。

[Heading 1] 19. 完成核心后的增强功能：动态编码模式
第一版动态模式把全部A端拉低，因此对间歇开路非常敏感，但两个低电平线路突然短接时不一定可见。只有当核心功能、实验和上位机全部稳定后，才增加动态编码检测。
增强思路：每条线发送不同的低占空比/伪随机开漏码 C_i(t)，B端实时检查接收到的码型是否等于预期码。出现瞬态桥接、错连时会产生编码失配。最终可以形成 Continuity Mode（高灵敏度间歇开路）与 Coded Mode（动态开路+桥接）两个模式。

[Heading 1] 22. 最终现场演示流程
1. 插入标准16芯线束，点击 LEARN，系统建立参考拓扑。
2. 插入错接/断路/桥接线束，系统自动指出具体针脚与 Expected / Actual。
3. 换回一根静态检测完全 PASS、但连接器存在间歇故障的线束。
4. 进入 DYNAMIC MODE，弯折/振动线束。FPGA捕获微秒级异常，屏幕冻结故障前后波形。
5. 展示事件列表：通道、时间戳、持续时间、重复次数；多通道异常时展示事件时间序列。
6. 最后展示量化数据：最低可靠故障脉宽、检测率、并发能力、MCU对比以及FPGA资源优化。
