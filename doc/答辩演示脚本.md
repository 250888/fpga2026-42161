# 瞬迹 答辩演示脚本（8–10 分钟）

目标：让评委在 8–10 分钟内依次看到——①系统自动重建 16 路线束拓扑（cls 5 → 0）；②人为制造开路 / 错接 / 短接，上位机逐帧捕获、cls 实时跳变；③一键导出带毫秒时间戳的证据文件。

---

## 1. 上台前检查清单（提前 10 分钟做完）

- [ ] EGO1 **已烧录**（断电/重插 USB 后必须重烧，JTAG 配置易失）
- [ ] J5 2×18 排线接牢；JA/JB 用 **2×10 公头**对接线束（不要杜邦线捅母座），红线对齐 pin1，17–20 针 NC 不接
- [ ] 演示线束：建议 16 根单根跳线逐路接 A_i↔B_i（方便现场拔一根、交叉两根）；用整条 1:1 IDC 排线则错接/短接动作不好做，以现场线材为准
- [ ] SW0 拨到 ON
- [ ] 演示电脑已用 Chrome/Edge 打开 `上位机.html`（提前开好页面、提前连过串口完成授权），按 **F** 进入页面自带全屏——**不要用浏览器 F11**，F11 只去掉浏览器边框，页面不会放大；F 模式按 **1920×1080 精确排布、整页正好一屏无滚动条**，状态词 62px、矩阵格 25px、连接图撑满面板，录视频和投影都用它
- [ ] 台下预演过一轮完整流程；Vivado 与 bit 文件在演示电脑上可随时重烧
- [ ] 浏览器下载目录设为桌面（导出证据用）

## 2. 分步演示脚本

时间轴合计约 8.5 分钟。每步的「预期」以实测为准，下方数值是 16 路 1:1 基准线束接好时的预期值。

| 步 | 时间 | 操作 | 屏幕上应看到 | 讲解要点（一句话） |
|---|---|---|---|---|
| 1 | 0:00–0:40 | 开场：手指 EGO1 + FE-16 扩展板 + 线束，不做任何点击 | 硬件就位，页面已打开（状态「未连接」） | "FPGA 开漏驱动分时扫描 16 路 → 被测线束 → 4.7k 上拉 + 施密特反相整形回采，一帧算完 256 个连接点，48 字节帧从 115200 串口发出，约 4.2 ms 一帧" |
| 2 | 0:40–1:20 | 点「连接串口」→ 选 COM4 | 圆点变绿「COM · 115200 8N1」；帧/秒 ≈ 240；矩阵 16 个对角格墨色点亮；连接数 16/16；**cls = 5 NO_REF** | "此刻系统只是在报告实测到的导通关系，还不知道'正确接法'应该是什么——NO_REF 就是还没学习基准" |
| 3 | 1:20–1:50 | 按 EGO1 的 **BTN1** 学习基准；随后点「导出证据」 | 大字 NO_REF(5) → **PASS(0)**，时间线出现「状态 NO_REF → PASS」+ 16 条「A_i → B_i 连接建立」；证据文件存盘（**证据①**） | "按下的瞬间 FPGA 锁存当前 16×16 矩阵为基准，之后每帧与基准逐 bit 比对，差一位就报故障" |
| 4 | 1:50–3:20 | **制造开路**：拔掉一根线（建议 A5↔B5）；停 3 秒；点「导出证据」（**证据②**）；插回 | 连接数 16 → **15/16**；Open 条带第 5 格变灰；矩阵 A5 行变灰白；时间线「ch 5 连接丢失」；**cls 跳 1 OPEN**（琥珀）；插回后 cls 回 0、时间线「连接建立」 | "断线后该通道回读为上拉的空闲电平，矩阵对应位清零、帧内 open_flags 置位，从断到报只隔一帧——约 4.2 ms" |
| 5 | 3:20–5:00 | **制造错接**：交叉 A3/A11（A3 改接 B11、A11 改接 B3）；停 3 秒；导出（**证据③**）；复原 | 矩阵两个**非对角**格变红（A3×B11、A11×B3），A3、A11 对角格灭；SVG 出现两条红色交叉曲线；连接数仍 16/16；**cls 跳 2 MISWIRE**（红） | "接错线时连接总数不变，但导通位置偏离基准对角线——矩阵逐点比对把错接精确到具体 A→B 对，不是只知道'坏了'" |
| 6 | 5:00–6:30 | **制造短接**：用一根跳线把两个通道并接（如 B2 与 B3）；停 3 秒；导出（**证据④**）；断开短接 | **cls 跳 3 BRIDGE**（红）；矩阵对应行可见并联导通（以实测为准）；断开后 cls 回 0 | "多路并联的回读特征与单路导通、开路都不同，FPGA 分类为短接而不是开路——开路、错接、短接三类故障在协议里是三个独立状态码" |
| 7 | 6:30–7:30 | **瞬态留痕**：快速插拔同一根线 2–3 次；导出（**证据⑤**） | 时间线连续刷出多条 add/del，每条带毫秒时间戳；矩阵对应格随之闪；**顶部「实时连接数」条带出现琥珀→橙→琥珀的缺口，恢复后缺口仍保留** | "FPGA 侧扫描是 μs 级的，上位机每 4.2 ms 比对一帧。看这条带子——每格是一帧，断线的那几帧被永久记在条带上，插回去颜色恢复了但缺口还在。这就是'线什么时候断'的动态诊断" |
| 8 | 7:30–8:30 | 收尾：打开导出的 `xunji_证据_*.txt` 投屏展示；若硬件已出岔子则切「演示」模式把流程讲完 | txt 头部含导出时间、当前 cls、连接数，正文是带时间戳的事件序列 | "证据文件是全事件时间线导出，可直接附进报告；上位机是单文件 HTML，评委拿 U 盘拷走就能复现" |

### 三种故障制造方法速查

| 故障 | 怎么做 | 预期 cls | 预期界面 | 复原动作 |
|---|---|---|---|---|
| 开路 | 拔一根线（如 A5↔B5） | 1 OPEN | 连接数 15/16，Open 条带一格变灰 | 插回，cls 回 0 |
| 错接 | 交换两根（A3→B11、A11→B3） | 2 MISWIRE | 非对角红格 ×2，SVG 红交叉线，连接数仍 16 | 换回原位 |
| 短接 | 一根跳线并接两个通道（如 B2–B3） | 3 BRIDGE（以实测为准） | 矩阵见并联导通 | 断开跳线 |

**纪律**：先学习好基准再制造故障；**一次只做一种**，做完复原、确认 cls 回 0，再做下一种（多种故障并存时 cls 取值以实测为准）。

## 3. 现场应急预案

| 情况 | 处置 | 话术 |
|---|---|---|
| 连接数不够 16（部分通道不通） | ① 查 JA/JB 是否公头对接、红线对齐 pin1、17–20 NC 未接；② 看 Open 条带定位是哪几路；③ 缺失通道若等间隔出现（如 3、6、9 路）直接查排线与连接器；④ 来不及修就只演示已通通道，用矩阵与 SVG 讲原理 | "缺的这几路 Open 条带已定位到通道号，这类接触问题排查路径已写进使用手册" |
| 串口连不上 / 端口列表为空 | ① 设备管理器确认 COM 号；② 关掉串口助手、`xunji read`、占用该口的其它标签页；③ 拔插 USB 重连；④ 都不行 → 点「演示」按同一套流程讲（界面完全一致，仅数据是模拟） | "上位机有演示模式，界面与真机一致，我们用它把比对逻辑讲清楚" |
| 页面连上但没数据（帧/秒 0） | SW0 没拨 ON，或 FPGA 断过电未重烧 → 拨 SW0 / 现场 Vivado 重烧 | "Artix-7 的 JTAG 配置易失，断电重烧已写成操作手册的固定步骤" |
| 按 BTN1 后 cls 不变 0 | 确认 SW0 ON、线束接好后再按一次；仍不行检查线束实际导通与基准一致性 | "学习动作只在扫描进行中生效，我们重按一次" |
| cls 多种故障来回乱跳 | 回到"一次一种故障"纪律；每次复原后停 1 秒再做下一个 | — |
| 时间线刷太快评委看不清 | 不追行，直接指时间戳讲毫秒精度，随后导出证据投屏细看 | — |
| 投影分辨率/字太小 | 按 **F** 进页面自带全屏（状态词 62px、连接数 54px、矩阵格 26px、版心 1720px），比浏览器 F11 更适合投影；矩阵与读数带是页面上最大的元素，讲解时用鼠标指格子 | — |
| 页面长时间无数据、状态词变灰「数据已停止」 | 1.5 秒没收到字节：SW0 被拨回 OFF / FPGA 断过电未重烧 / USB 松动。拨 SW0、重烧、插紧 USB 即可，数据恢复后状态点自动变绿，不用重新连接串口 | "FPGA 的 JTAG 配置易失，断电重烧是固定操作步骤" |

## 4. 证据留存清单

| 序号 | 时机 | 文件里应有什么 | 用途 |
|---|---|---|---|
| ① | 学习完成、cls=0 后 | 状态 NO_REF → PASS + 16 条连接建立 | 基准拓扑证据 |
| ② | 开路复原前 | 状态 → OPEN + 「ch n 连接丢失」 | 开路捕获证据 |
| ③ | 错接复原前 | 状态 → MISWIRE | 错接定位证据 |
| ④ | 短接复原前 | 状态 → BRIDGE（以实测为准） | 短接分类证据 |
| ⑤ | 快速插拔后 | 密集的 add/del 毫秒时间戳序列 | 瞬态捕获证据 |

- 导出文件名：`xunji_证据_<UTC时间戳>.txt`（文件头「导出时间」为本机时间）。建议下载后立刻改名加注，如 `证据②_开路_PASS.txt`，避免混淆。
- 导出内容是**事件时间线**（界面显示最近 300 条，导出最多 3000 条），不是原始帧。
- **演示模式下导出的证据是模拟数据，不作为正式证据**；正式证据必须在状态栏显示「COM · 115200 8N1」时导出。
